# План: безопасность клиентской сессии и навигация Account → Cart

Дата: 2026-09-15

Статус: P0/P1 реализованы (Tasks 1–4, 6–7). Task 5 (hash/rotation идентификатора) и Task 8 (управление устройствами) остаются P2 и не входят в эту итерацию.

## Цель

Сделать поведение клиентского аккаунта понятным для пользователя и завершить защиту Shopify Customer Account-сессий на сервере.

Работа должна решить две проблемы:

1. Пользователь не должен оставаться авторизованным дольше установленного срока только потому, что refresh token продолжает работать.
2. Переход из `My Account` в `Current cart` не должен ощущаться как переход на тупиковую страницу без понятного возврата.

## Исходное состояние до реализации

### Клиентская авторизация

- Аккаунт покупателя обслуживает Shopify Customer Account API, а не Google-аккаунт Chrome и не локальная email/password-система Synarava.
- В браузере хранится cookie `synarava-shopify-customer-session` со случайным идентификатором серверной сессии.
- Cookie создаётся на 30 дней и в production имеет `HttpOnly`, `Secure` и `SameSite=Lax`.
- Access token, refresh token и ID token хранятся в таблице `ShopifyCustomerSession` в зашифрованном виде.
- Когда access token приближается к окончанию срока, сервер обновляет его через refresh token.
- OAuth-вход использует PKCE, `state`, `nonce` и проверку подписи ID token.
- Выход удаляет текущую запись сессии, cookie сессии и cookie корзины, после чего вызывает Shopify logout endpoint.

Основные файлы:

- `app/api/auth/shopify/route.ts`
- `app/api/auth/shopify/callback/route.ts`
- `app/api/auth/shopify/logout/route.ts`
- `lib/shopify/customer-account/session.ts`
- `lib/shopify/customer-account/session-store.ts`
- `lib/shopify/customer-account/crypto.ts`
- `lib/shopify/customer-account/id-token.ts`
- `prisma/schema.prisma`

### Обнаруженный риск

Поле `ShopifyCustomerSession.expiresAt` отражало срок access token, а не абсолютный срок пользовательской сессии. При refresh значение обновлялось. Ограничение в 30 дней существовало только в cookie браузера.

Следствия:

- браузер штатно удалял cookie через 30 дней, но серверная запись оставалась;
- в коде не было явного абсолютного server-side TTL для сессии;
- похищенный идентификатор сессии потенциально можно повторно предъявить после окончания browser cookie, пока Shopify принимает refresh token;
- заброшенные записи с зашифрованными токенами могут храниться без срока удаления;
- ответ Shopify `401` при загрузке профиля не удалял недействительную локальную сессию немедленно.

Это не означает, что текущая схема полностью небезопасна: идентификатор сессии имеет высокую энтропию, cookie защищена от JavaScript, OAuth-поток проверяет подлинность ответа, а токены зашифрованы. Проблема заключается в неполном контроле жизненного цикла сессии на стороне Synarava.

### Навигация Account → Cart

- Кнопка `Current cart` на overview ведёт на самостоятельный маршрут `/{locale}/cart`.
- На desktop из корзины можно перейти в `MY ACCOUNT` через глобальный header.
- На mobile ссылка на аккаунт находится внутри navigation drawer.
- Browser Back также работает, если пользователь пришёл из аккаунта в той же вкладке.
- В самой корзине не было контекстной ссылки `Back to My Account` или breadcrumb.
- Пустая корзина предлагает только перейти к товарам; заполненная — продолжить покупки или перейти к checkout.

Из-за этого маршрут технически не тупиковый, но визуально и семантически теряет контекст аккаунта.

### Раздел Security

Вкладка `Security` только объясняла passwordless-вход и содержала кнопку выхода с текущего устройства. Управления безопасностью, истории входов или списка сессий в ней не было. Название обещало больше возможностей, чем предоставлял интерфейс.

## Целевое поведение

### Сессия

- Срок авторизации проверяется сервером, а не только браузером.
- У сессии есть отдельные сроки:
  - срок access token от Shopify;
  - абсолютный срок клиентской сессии Synarava;
  - при необходимости — срок неактивности.
- Просроченная, повреждённая или отозванная сессия удаляется из базы и перестаёт считаться авторизованной.
- Cookie не может жить дольше server-side сессии.
- Старые записи очищаются автоматически.
- В UI пользователь понимает, почему он авторизован и как завершить сессию.

### Корзина

- Пользователь, пришедший из аккаунта, видит очевидный путь обратно.
- Возврат не зависит от browser history, поэтому работает при прямом открытии URL и в новой вкладке.
- Глобальная навигация остаётся доступной.
- Поведение одинаково понятно на desktop и mobile.

## Предлагаемые продуктовые решения

1. Оставить Shopify источником истины для customer identity, заказов и адресов.
2. Не связывать customer-сессию с Google-профилем браузера: это разные системы идентификации.
3. Ввести server-side абсолютный срок сессии. Рекомендуемый исходный вариант — 30 дней.
4. Рассмотреть отдельный idle timeout. Рекомендуемый вариант для обсуждения — 14 дней без активности.
5. Не привязывать сессию жёстко к IP: мобильные сети, VPN и смена сети создадут ложные выходы. IP можно использовать только как сигнал риска и не хранить дольше необходимого.
6. Добавить в корзину детерминированную ссылку на `/{locale}/profile`, а не кнопку на основе `router.back()`.
7. Переименовать `Security` в `Sign-in & security`, если на первом этапе там останутся только сведения о входе и logout.

## Риски и способы снижения

| Риск | Влияние | Снижение |
| --- | --- | --- |
| Слишком короткий TTL раздражает покупателей | Среднее | Согласовать абсолютный и idle TTL; при необходимости добавить явный `Remember me` |
| Refresh и logout выполняются параллельно | Высокое | Атомарное обновление/удаление, тест конкурентных запросов |
| Изменение схемы разлогинит всех покупателей | Среднее | Явная миграционная политика и контролируемый rollout |
| Очистка удаляет ещё действующие сессии | Высокое | Удалять только по `sessionExpiresAt`, использовать UTC и тестировать границы времени |
| Device metadata увеличивает объём персональных данных | Среднее | Минимизировать поля, установить retention, не показывать точный IP |
| Контекстная ссылка перегружает cart header | Низкое | Вторичный визуальный вес, проверка на mobile и рядом с checkout CTA |

## Не входит в базовый объём

- Замена Shopify Customer Account на локальную систему паролей.
- Связывание входа Synarava с Google-аккаунтом Chrome.
- Жёсткая IP-привязка сессии.
- Сохранение полных IP-адресов или fingerprinting устройства без отдельного privacy review.
- Перестройка checkout flow, если она не требуется для корректной инвалидации customer session.

## Открытые решения перед реализацией — принятые решения

1. **Срок сессии**: 30 дней absolute TTL (`CUSTOMER_SESSION_ABSOLUTE_TTL_SECONDS`, `lib/shopify/customer-account/config.ts`) + 14 дней idle timeout (`CUSTOMER_SESSION_IDLE_TIMEOUT_MS`). Оба значения — единственный источник правды, используются и cookie `Max-Age`, и записью `sessionExpiresAt`.
2. **Remember me**: не вводится в этой итерации — срок единый для всех входов (YAGNI; можно добавить отдельным срезом, если продукту это понадобится).
3. **Security tab**: на этом этапе только переименование в `Sign-in & security` + отображение срока текущей сессии и явного пояснения про Shopify/Google. Управление несколькими устройствами (Task 8) остаётся отдельным P2-релизом.
4. **Ссылка Cart → Account**: всегда ведёт на `/{locale}/profile` (overview), а не на последнюю посещённую секцию — самый предсказуемый вариант и не требует дополнительного состояния.
5. **Миграция существующих сессий**: без принудительного logout. Существующие записи получают `sessionExpiresAt = createdAt + 30 дней` (миграция `20260915120000_split_shopify_session_expiry`), то есть не позднее исходного 30-дневного окна cookie — без новой отсрочки, но и без разового массового разлогинивания.
