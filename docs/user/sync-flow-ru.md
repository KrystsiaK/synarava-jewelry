# Синхронизация с Shopify для владельца каталога

## Goal

Как пользоваться синхронизацией в **текущем** admin на staging: проверка Shopify
из верхней панели, окно конфликтов, выбор стороны, превью и Apply. Сначала
создаёте товар в Synarava, потом пушите в Shopify; SKU назначаете с явным
выбором семейства.

## Before you start

- Вы вошли в admin на **staging** (или в таком же окружении).
- Учётные данные Shopify Admin и привязка магазина совпадают с нужным шопом.
- См. также (EN): [Shopify sync button](/admin/help/shopify-sync-button),
  [Add a product](/admin/help/add-a-product),
  [Sync collections](/admin/help/sync-collections).

:::good-to-know
Две копии коммерческих данных. **Shopify** (слева) — загруженная, в окне
конфликтов только для чтения. **Synarava** (справа) — то, что вы правите.
Проверка сама по себе **не пишет** в Synarava. Пишет только человек через
**Apply** после превью.
:::

## Steps

:::steps
### Кнопка Shopify в верхней панели

В admin в верхней панели — контроль Shopify. Полный fetch+compare каталога
идёт **только** отсюда (клик) и один раз за сессию входа. После Save / Apply /
Push / Pull / назначения SKU перепроверяется **только этот** товар или
коллекция. **Show conflicts** Shopify заново **не** тянет — читает последний
результат сравнения.

| Состояние | Смысл |
| --- | --- |
| **Shopify current \<time\>** | Последняя успешная полная проверка |
| **Checking Shopify…** | Идёт полная проверка — Save / Apply заблокированы |
| **Check failed** | Проверка не завершилась — нажмите ещё раз |
| **Shopify disconnected** | Нужно починить credentials / приложение / привязку |

Если Shopify отвечает лимитом запросов, admin показывает понятное сообщение вроде
**Shopify is rate-limiting requests; wait a few seconds and try again**.
Подождите и снова нажмите кнопку в панели. Не долбите Push / Pull / Apply,
пока это сообщение актуально.

### Окно конфликтов

Когда баннер показывает **N conflicts**, откройте **Show conflicts**. Один
общий UI:

- **Слева = Shopify**
- **Справа = Synarava (ours)**

Клик по ячейке выбирает сторону. Повторный клик снимает выбор. **Take Shopify
for all** / **Keep ours for all** только *выделяют* строки, ничего не пишут.
**Apply (N)** открывает превью. Запись — только после подтверждения.

В превью направление выглядит так: **Price: Shopify → Synarava**,
**Create item: …**, или **Remove item: Shopify → Synarava** (после
подтверждения будет удалена копия на стороне Synarava — читайте превью
внимательно).

### Карточка «Product data (N fields)»

Если коммерческое расхождение требует **целого** Pull/Push (теги, статус,
cost и т.п.), в сравнении одна базовая карточка — **Product data (N fields)**.
Выбор стороны на ней выбирает **всю группу** одним действием. Поэтому один
клик «забирает всё»: это один юнит синхронизации, не N отдельных писателей
полей. Если все расхождения точечные — у каждого поля своя карточка.

### Конфликты по языкам

Общие коммерческие факты (цена, картинка, статус…) живут на вкладке
**English / base**. Конфликт только португальского названия подсвечивает
**PT** (и итог по товару), не EN. Строки переводов (PT/RU, …) отдельны от
группы **Product data (N fields)**. Откройте вкладку с точкой, выберите
сторону, Apply с превью.

### Создать в Synarava → push в Shopify

1. **Catalog → Products** — новый товар (имя + цена обязательны).
2. **Save product** — черновик пока только в Synarava (**Only in Synarava**).
3. Назначьте уникальный **SKU** (см. ниже), иначе Create недоступен.
4. В шапке товара — **Create in Shopify**: push, подтверждение резерва SKU,
   перепроверка товара, при совпадении копий — путь к **In sync**.

Дальше: **Push** / **Pull** / **Resolve** из той же шапки. **Save product**
всегда сохраняет полный локальный товар; sync не заменяет Save.

### Назначение SKU (явное семейство, неизменяемый ledger)

Если подключён portable SKU-сервис, в Inventory: **Family → Preview → Confirm**
(или **Resume** для незавершённого резерва):

- Семейство выбираете **сами**. Автовыбора нет.
- Preview и Confirm неактивны, пока семейство не выбрано.
- Уходит ровно выбранное семейство — без тихого «первого в списке».
- **Ledger неизменяем**: неверное семейство навсегда резервирует этот путь.
  Сначала Preview, Confirm — только когда кандидат SKU верный.

Если сервис не настроен — SKU вводите вручную до Create in Shopify.

### Удаление позиции

Конфликты присутствия — те же левая/правая ячейки. Выбор стороны может создать
или удалить. В превью **Remove item: Shopify → Synarava** значит: после
Confirm копия в Synarava будет удалена. Смотрите before → after и счётчики
внизу до подтверждения.
:::

Описано только то, что есть на staging **сейчас**. То, что ещё строится —
помечено **coming** ниже.

## What if...

:::what-if
### Сообщение про rate-limit

**Cause:** Shopify Admin API ограничил частоту запросов.

**What to do:** Подождите несколько секунд и повторите одну проверку или одно
действие. Не запускайте параллельно много Push / Apply.

### Create in Shopify неактивен

**Cause:** Обычно `SKU required` или `Save changes first`.

**What to do:** Сохраните, назначьте/подтвердите SKU с явным семейством, затем
Create.

### Один клик выбрал много полей

**Cause:** Вы выбрали сторону на **Product data (N fields)**.

**What to do:** Так и задумано для whole-item sync. Снимите выбор с карточки,
если нужен другой сценарий.
:::
