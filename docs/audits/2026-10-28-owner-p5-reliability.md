# Для владельца — фаза 5: фоновые процессы и аварии

**Дата:** 28 октября 2026 (Europe/Lisbon)  
**Технический отчёт:** [2026-10-28-reliability.md](2026-10-28-reliability.md)

## Что мы нашли

1. **REL-001 / REL-002 (высокий)** — вебхук продуктов: кривой JSON может крутиться в бесконечных ретраях Shopify; плюс небезопасный разбор больших id (как DEAD-001).
2. **REL-003 (средне)** — без заголовка id доставки вебхук не дедуплицируется.
3. **REL-004 (средне)** — cron Mission Control collector без «аренды»: два тика могут пересечься (у проверки каталога аренда есть).
4. **REL-005 (средне)** — лимит Shopify throttle считается **внутри одного процесса**; несколько реплик могут вместе упереться в лимит API.
5. **REL-006 (средне, политика)** — в истории уже были миграции с DROP (не только «добавить колонку»). Будущие опасные миграции — только с runbook и бэкапом.
6. **REL-007** — пути скриптов бэкапа/отката в runbook **совпадают с репозиторием** (ок).

## Что это значит для бизнеса

- Вебхуки = актуальность остатков/каталога/отзывов без ручного синка. Ошибки здесь = «тихие» рассинхроны или шторм ретраев.
- Collector без замка = риск ложных Telegram-алертов или гонок статуса на хабе.
- Прошлые DROP-миграции нормальны для уже сделанных cutover; **новые** без процедуры = риск повторить инцидент с БД.
