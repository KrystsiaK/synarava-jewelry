# Для владельца — фаза 1: синхронизация с Shopify

**Дата:** 28 октября 2026 (Europe/Lisbon)  
**Технический отчёт:** [2026-10-28-sync-adversarial.md](2026-10-28-sync-adversarial.md) (PR аудита, не мержить без решения)

## Что мы нашли

Проверили «правила честности» синхронизации каталога: сравнение наших данных и Shopify, медиа, блокировки опасных действий.

1. **SYNC-ADV-002 (важно)** — для коллекций система иногда подписывает поля как «продуктовые». В интерфекте конфликтов подпись/секция может быть неверной для коллекции.
2. **SYNC-ADV-001 (средне)** — у расхождений в переводах не хватает служебных меток контракта. На работу магазина напрямую не бьёт, но усложняет разбор конфликтов.
3. **SYNC-ADV-004 (низко)** — вспомогательный список id медиа не убирает дубликаты (основной push уже чистит).

Остальные проверенные правила (детерминизм сравнения, cost не уходит в linked push, multi-variant Keep ours блокируется, «успех сходимости» при живом конфликте не врёт) — **держатся**.

## Что это значит для бизнеса

- Риск ошибочной подписи конфликта у **коллекций** — человек может принять не то решение в UI.
- Магазин и оплата от этих пунктов сами по себе не ломаются; это про админку синка.

## Что делать дальше

1. Отдать разработчику фикс **SYNC-ADV-002** (типизированный lookup по PRODUCT/COLLECTION) — приоритет выше остальных фазы 1.
2. Затем лёгкий фикс меток переводов (**001**) и дедуп id (**004**).
3. Гипотезы H1/H2 из техотчёта **не чинить**, пока не воспроизведём на реальных данных.
