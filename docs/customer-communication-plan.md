# План коммуникаций с клиентом Synarava

## Что означает «недостаточно»

Тестовое письмо из редактора Shopify проверяет только шаблон и возможность
ручной тестовой отправки. Оно не доказывает, что реальный покупатель получит
письмо после ухода из checkout.

Проверка 17 сентября 2026 года:

- Shopify Messaging: письмо `Complete your order` и автоматизация
  `Recover abandoned checkout` имеют статус **Active**.
- Тестовое письмо получено на `synarava.shop@gmail.com`. Его кнопка ведёт на
  `shopify/abandonment/mock`: это демонстрационная ссылка письма с меткой
  `[TEST]`, а не recovery URL реального checkout.
- В полученном тестовом письме был склеен заголовок. После исправления текст
  `Ready to checkout?` сохранился при повторном открытии редактора; письмо и
  автоматизация снова имеют статус **Active**. Старое полученное письмо от
  этого не меняется.
- Тестовый checkout `#67988629356893` создан с витрины `shop.synarava.com`.
  Shopify показывает источник `Synarava Development`, товар Golden Rombo Chain
  Bracelet и статус `Not Recovered`.
- В карточке checkout указано `No automations were triggered`; контакт отмечен
  как `Not subscribed to any channels`. Чекбокс согласия в незавершённой форме
  был выбран, но подписка в Shopify не появилась.

Следовательно, **сквозная отправка письма о брошенном checkout с текущей
headless-витрины не подтверждена и сейчас не должна считаться работающей**.
Статус Active сам по себе не является критерием готовности.

## Границы ответственности

| Событие | Кто должен отправлять | Статус и следующий шаг |
| --- | --- | --- |
| Заказ создан, платёж, отмена, возврат, доставка | Штатные customer notifications Shopify | Проверить тестовым заказом, не дублировать письмами Synarava |
| Брошенный checkout с `shop.synarava.com` | Решение, совместимое с headless-каналом | Не считать Shopify Messaging рабочим, пока реальный checkout не запустит автоматизацию и письмо не дойдёт |
| Welcome, подборки, повторные продажи | Маркетинговый сервис после явного согласия | Не включать до фиксации доказательства согласия и отписки |
| SMS | Пока не запускать | Отдельно проверить покрытие стран, согласие, стоимость и доставку |

Ответы клиентов на письма о заказах должны приходить на подтверждённый владельцем
адрес `synarava.shop@gmail.com`. Отображаемый Shopify адрес отправки может
отличаться, пока используется публичный Gmail-домен.

## Порядок работ

### 1. Проверить служебные уведомления на тестовом заказе

- [ ] В Shopify убедиться, что включён именно Test Payment Gateway, затем с
  `shop.synarava.com` оформить один тестовый заказ на
  `synarava.shop@gmail.com`. Финальное нажатие оплаты выполняет владелец.
- [ ] Проверить в почте письмо о подтверждении заказа, язык, отправителя,
  ответ на письмо, товар, сумму и ссылки. Сверить номер заказа с Shopify Admin.
- [ ] На тестовом заказе проверить доступные безопасные сценарии оплаты/отмены
  и соответствующие письма; доставку тестировать только без реальной отправки.

**Критерий готовности:** заказ и платёж видны в Shopify, ожидаемое письмо
получено и его данные совпадают с заказом. Отправка тестового письма из редактора
не заменяет эту проверку.

### 2. Определить поддерживаемый путь для headless recovery

- [ ] Подтвердить с текущей документацией Shopify, какие каналы поддерживает
  `Recover abandoned checkout` и можно ли атрибутировать корзины нашей витрины
  к поддерживаемому каналу без подмены commerce-модели.
- [ ] Проверить, доступен ли для Synarava официальный Buy Button путь с
  сохранением текущего UX корзины, Shopify Checkout и локализации. Решение
  принимать только после реального теста канала и доставки.
- [ ] Если поддерживаемый нативный путь невозможен, выбрать готового email-
  провайдера для **доставки**, а не строить собственную почтовую инфраструктуру.
  Shopify остаётся источником checkout, заказа и recovery URL. Проверить доступ
  к Admin API `abandonedCheckouts`, нужные scopes и ограничения protected
  customer data до реализации.

**Критерий готовности:** выбран один путь и задокументированы требуемые доступы,
стоимость, обработка согласия и способ остановки письма после заказа. Не
расширять аудиторию шаблона на `All customers` ради обхода проблемы.

### 3. Сделать отправку с согласием и защитой от дублей

- [ ] Зафиксировать источник, текст/версию согласия, время и статус подписки.
  Один локальный `marketingOptIn` без этих данных недостаточен; сверять статус
  с Shopify или выбранным провайдером до каждой отправки.
- [ ] Добавить один recovery email с персональной ссылкой Shopify и задержкой,
  которую можно проверить. Не включать второе напоминание и скидку в первом
  релизе.
- [ ] Подавлять отправку после оплаты, отписки, недоступности товара и уже
  отправленного письма. Секретную recovery URL не писать в логи, аналитику или
  публичные страницы. Обеспечить повторяемость задач без дублей.
- [ ] Предусмотреть unsubscribe, журнал отправок/ошибок и понятный способ
  выключить автоматизацию. Не отправлять маркетинговое письмо при отсутствии
  подтверждённого согласия.

**Критерий готовности:** один подходящий checkout даёт не более одного письма;
неподписанный клиент, завершённый заказ и отписавшийся клиент не получают его.

### 4. Проверить сквозной сценарий

- [ ] Создать новый checkout с витрины, использовать тестовый адрес с заранее
  подтверждённой подпиской и оставить checkout незавершённым. Shopify обычно
  показывает abandoned checkout не сразу; дождаться записи в Admin.
- [ ] Убедиться, что запуск автоматизации/задачи виден в журнале, письмо
  получено, а ссылка возвращает к нужному Shopify checkout и товарам.
- [ ] Повторить с адресом без согласия: письма быть не должно. Повторить с
  завершённым тестовым заказом: recovery email должен быть подавлен.
- [ ] Проверить EN/PT шаблоны, мобильный вид, адрес для ответа и отсутствие
  тестовых данных в реальном письме.

**Критерий готовности:** подтверждены запись checkout, запуск, доставка,
корректная ссылка и подавление лишних отправок. Только после этого отмечать
recovery как работающий на `shop.synarava.com`.

## Необходимые доступы и решения

Для тестового заказа достаточно текущего Shopify Admin и доступа владельца к
почте. Для headless recovery после выбора пути могут понадобиться доступ к
настройкам домена для аутентификации отправителя, аккаунт email-провайдера,
разрешённые Shopify Admin API scopes и одобрение доступа к customer data.
Секреты вводятся владельцем в настройки окружения и не помещаются в этот файл
или переписку.

До выполнения пунктов 2–4 Shopify-автоматизацию можно оставить Active для
поддерживаемых каналов, но нельзя использовать её статус как обещание писем
покупателям с headless-витрины.
